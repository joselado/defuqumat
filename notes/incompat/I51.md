# I51. Partial dynamical matrix (`atoms=`) x symmetry

Status: done for a subset that is a union of orbits; the refusal stays, sharpened, for any
other subset.

## The number

The check is the entry's own, both halves of it: the subset's block against the whole cell's
block of the same symmetrised calculation, and the subset on the wedge against the subset on
the same closed sample run `nosym`. Each figure is one run (the route is deterministic on one
core), on D22, CPU, one thread, at `tr2 = 1e-24` and a CG threshold of 1e-12 (`IDENTITY` in
`tests/regression/test_phonons.py`), max |difference| in Ry/bohr^2 on force constants of
0.22 to 0.39:

| cell | subset | against | difference |
|---|---|---|---|
| `alas-raman-wedge.in` (nc, 8 k) | `(0,)` | whole wedge block | 6.3e-11 |
| `alas-raman-wedge.in` | `(1,)` | whole wedge block | 1.7e-10 |
| `alas-piezo-tiny-wedge.in` (US, 3 k) | `(0,)` / `(1,)` | whole wedge block | 5.1e-12 / 3.7e-10 |
| `alas-piezo-tiny-paw-wedge.in` (PAW, 3 k) | `(0,)` / `(1,)` | whole wedge block | 2.6e-12 / 3.6e-11 |
| `alas-raman-wedge.in` | `(0,)` | `(0,)` on `alas-raman.in` (`nosym`, 64 k) | 6.2e-10 |
| fluorite Si + 2 As, metal (inline in the test) | `(1, 2)` / `(0,)` | whole wedge block | 1.5e-11 / 1.7e-10 |

The residue is the loop's stop, not the symmetrisation, and three numbers say so. The two
whole-cell routes on the same AlAs pair (wedge against `nosym`) differ by **7.9e-10** at the
same settings, so 2e-9 is the floor the identity is held at (`CLOSED_SUBSET_TOLERANCE`).
At `tr2 = 1e-28` and a CG threshold of 1e-14 the AlAs nc blocks fall to **3.9e-14** and
**4.7e-13**, so the residue moves with the convergence. And the negative controls, the
subset's in-loop `symdvscf` switched off and then its `symdynph_gq` switched off, read
**2.7e-3** and **5.3e-3**, six orders above the bound, so a wrong symmetrisation could not
pass. The fluorite cell is there because its two As atoms are one orbit exchanged by the
inversion, so the subset's own atom table is a non-trivial permutation; `|D_12|` between them
is 0.18, so the block is not two independent ones.

Harness and logs on D22: `/l/ladovj1/review/incompat/I51/` (`run1.log` the tests with the
differences printed, `run2.log` the floor, the tight loop and the controls, `harness.py`,
`run3.log` the final tests).

## What was missing

The entry's stated term, "a subset needs the stabiliser of the subset", was wrong. The k-set
is the wedge of the whole group, so completing the wedge sum for the response to atom `a`
along `i` reads `drho_{S^-1(a),j}` for every operation `S` of the whole group
(`symmetrize_atom_displacement_density`). Averaging over the subset's stabiliser would be an
average over a group the k-set was not reduced by, and wrong rather than slow. What is
available is the case where every operation maps the subset into itself, which is a union of
orbits, and then every symmetriser acts on the partial stack through the subset's own atom
table:

- `defuqumat/system/symmetry.py`: `orbit_closure` and `subset_atom_mapping` (new), the
  `(nsym, len(atoms))` table in the subset's own indices.
- `Calculation.symmetrize_atom_displacement(fields, atoms=None)` and
  `Calculation.symmetrize_atom_pair_tensor(tensors, atoms=None)` (`scf/driver.py`).
- `_symmetrize_modes` and `symmetrize_becsum_modes` (`response/phonon.py`) take `atoms`;
  PAW's `apply_atom_displacement` needed no change, since its `mapping` indexes only the
  displaced axis and the `becsum` atoms keep its own full table.
- `screening_loop`, `_whole_k` and `chunked_phonon.StreamedDisplacements.prepare` pass the
  subset through; `_phonons_of` now applies `symdynph_gq` to the subset's block (before, it
  relied on the run being `nosym`).
- `_require_a_subsettable_regime` refuses with symmetry only a subset that is not closed,
  and names the smallest closed subset containing it (`atoms=(0, 1)` for silicon's
  `atoms=(0,)`, where half the operations exchange the sublattices).

Still refused: a non-closed subset with symmetry (`test_a_subset_of_a_symmetrised_run_is_refused`,
and the fluorite `atoms=(1,)` inside `test_a_closed_orbit_of_two_atoms_is_the_whole_block`),
the acoustic sum rule on a subset, a subset of a response walked a k-chunk at a time
(I54, untouched), and, new, a closed subset with symmetry on the streamed route
(`dynamical_matrix`, after `_streams` decides the route): the subset is threaded through
`StreamedDisplacements.prepare` and the loop, but only the whole-k route was measured, so it
refuses there rather than run unmeasured. Before this change that regime was refused by the
general guard, so nothing that used to run is refused now. That guard is shown to fire by
`test_a_closed_subset_on_the_streamed_route_is_refused`, which forces `_streams` and builds
no ground state (run locally, 6 refusal tests in 4.5 s).

The three D22 runs were taken at commit `a4ff204` (run 1 at `af01a4d`, the same code with
the differences printed). The later commits add only the streamed-route refusal and its
test, which sit off the whole-k route the measured tests take, and this record.

Trap check (`trap-check` list) on the diff from `0feb4ee`: the two `np.asarray` are on the
host-side integer atom tables, never a tracer; the change is the wedge-completion
symmetrisation itself (trap 4), measured against the `nosym` grid and with two negative
controls; the identity is block by block, not an atom sum (trap 11). Nothing else applies.

Tests: `tests/regression/test_phonons.py::test_a_closed_subset_of_a_symmetrised_run_is_the_whole_block`
(nc, us, paw), `::test_a_closed_subset_on_the_wedge_is_the_subset_on_the_whole_grid`,
`::test_a_closed_orbit_of_two_atoms_is_the_whole_block`, all slow.
