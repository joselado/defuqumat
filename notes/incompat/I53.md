## What was missing, as found

The entry's term, "it differentiates the whole set", was the guard's wording and is true
only of two of the three Jacobians. The default Jacobian is a central difference of `F`,
which needs only evaluations of `F`, and an evaluation of `F` is one pooled SCF
iteration at a fixed `ethr`. What was missing was that evaluation and a protocol for
the solver's host decisions:

- `PooledScfResidual` (`defuqumat/scf/residual.py`) evaluates `F` as the pooled mixing
  loop does: `stream_start`/`stream_diagonalize` on the pool's rows, the eigenvalues
  gathered with `pools.gather_k(..., layout=)` for the occupations, and
  `stream_densities(..., reduce=pools.allreduce_sum)` for `rho`, `becsum`, `ns` and `tau`,
  the same calls with the same arguments as `run_scf`'s pooled iteration.
- Rank 0 alone runs GMRES, the line search and the convergence test; every evaluation is
  a collective it opens by broadcasting `[command, warm, x]`, and the other pools sit in
  `serve()` until `finish()` hands them the result (or `abort()` when rank 0 raises). This
  is the pooled loop's rule (every decision is rank 0's) carried to the solver, since
  pools with unequal thread counts can differ in the last bit and a solver run on every
  rank could take one more GMRES iteration on one of them.
- The warm start is an integer token, the same on every pool, and a pool keeps two
  stores (the warm start and the one just made), which is all `newton_krylov` reads.
  The warm store is copied before each solve because `stream_diagonalize` writes in
  place and the central difference evaluates `x + eps v` and `x - eps v` from one start.
  Memory: three of the pool's stores.
- `_refuse_under_pools` now receives the `jvp` backend's name instead of a flag, and
  refuses `autodiff` (it traces the whole-set eigensolver, which a host `PoolStore`
  cannot enter) and `sternheimer` (its solve reads every state).

Nothing in this path is differentiated, so the `np.asarray` calls in `_evaluate` cannot
cut a gradient. The broadcast vector is `float64` by construction, since it carries an
integer command and token besides the state; it is a transport buffer, not a compute
array.

**A refusal raised inside an evaluation hung the run (verifier, fix round).** Lifting
the guard let `occupations = 'tetrahedra'` and `'from_input'` reach the pooled route,
where `_weights` raised inside `_evaluate` on every rank after the eigenvalue gather:
rank 1 left `serve()` and waited at JAX's shutdown barrier, rank 0's wrapper called
`abort()`, a broadcast nobody answered, and both ranks exited -6 after 315 s with
"Shutdown barrier has failed / DEADLINE_EXCEEDED" and rank 0's traceback never printed
(`/l/ladovj1/review/incompat/I53/ver2/tetra.log`, Si 8k `nosym`, at `357c2609`). Before
I53 the entry guard stopped this input, and pooled mixing with tetrahedra runs, so the
earlier sentence here that this "is how the pooled mixing loop behaves too" was false
for it. The refusal is now `refuse_residual_occupations` (`defuqumat/scf/residual.py`),
raised first in `make_residual`, which every rank calls before `PooledScfResidual.of`,
and in `_refuse_under_pools` for any residual solver, so no rank enters a collective.
Measured on D22 at `18cf398`, worktree `/l/ladovj1/w-inc-I53-t2-v2`, one run
(`/l/ladovj1/review/incompat/I53/fix/tetra.log`, harness `tetra.py` beside it, the slow
test's input): one pool exits 1 after 3 s, and two pools exit 1 on both ranks after
10 s, each rank's stderr carrying "occupations='tetrahedra' has no differentiable
form", where the same input at `357c2609` hung both ranks for 315 s.

**Still not covered, and not measured**: any *other* exception inside an evaluation on
one rank, or on rank 0 between its broadcast and the collectives of `_evaluate` (a
Davidson failure, a memory error), still leaves the other ranks at a collective until
the pool heartbeat (`DEFUQUMAT_POOL_TIMEOUT`) takes them down, and `abort()` still
blocks when the raise came from inside `_evaluate`. No regime known to raise there is
left: magnetic fields and spirals are refused in `make_residual`, before the protocol,
and the two differentiating Jacobians at the entry guard and on the object.

**Magnetism and DFT+U under the pooled Newton route**, measured by the verifier at
`357c2609` (one pool against two, total energy; F evaluations / Newton steps equal on
every rank): symmetry on, a wedge k-set, 2 and 3 pools 3.6e-15 Ry (39/5,
`ver/sym.log`); Fe LSDA 9.2e-13 Ry (59/7, `ver/sym.log`); Fe noncollinear 1.0e-12 Ry
(59/7, `ver/ni.log`); Ni `nspin = 2` without U 9.9e-14 Ry (124/12, `ver/ni.log`); Ni
`nspin = 1` with U 5.5e-13 Ry (62/6, `ver/niu1.log`). Ni `nspin = 2` with U converges on
neither route (one pool: 30 Newton steps, accuracy 6.9e-6; two: 1e-3) and the energies
after the mixing tail differ by 1.85e-2 Ry; at a fixed state with a warm chain at
`ethr = 1e-13` (`ver2/fmap.py`, `ver2/fmap-ni.log`) the one-pool against two-pool `F`
falls from 6.6e-7 to 9.4e-9 over four evaluations, at or below the serial route's own
change between evaluations (1.9e-8), so that cell is hard for Newton and the pooled `F`
is right there too. The earlier sentence here that the pooled mixing tests cover DFT+U
was false: no test in `tests/` runs Hubbard under pools (`test_parallel.py`, the only
file that starts pools, has no `hubbard` or `ldau`).

The trap-check list was run against `git diff 126d6ec..HEAD -- defuqumat/`: no hit. Every
`np.asarray`, `float()` and `float64` added is in the host-side protocol of a function
that is never traced (traps 5 and 6), nothing walks the k axis outside the streamed
passes (trap 7), and the two inherited refusals were checked against this machine: the
`autodiff` one holds because the pool's store is host memory, the `sternheimer` one
because its solve reads every state (trap 12).

The fix round's diff (`357c2609..18cf398`, `defuqumat/` only) was run against the
same list: no hit. It adds one host-side function that reads the static string
`system.occupations`, called from `_weights` (inside a trace, where it reads no array),
`make_residual` and `_refuse_under_pools`; nothing in it is differentiated, holds a
dtype or walks the k axis. `_refuse_under_pools` has one caller, `run_scf`, which
passes the `jvp` name or `None`.
