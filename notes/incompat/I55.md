# I55. Self-consistent frequency-domain hierarchy x two FFT grids (norm-conserving, `ecutrho > 4 ecutwfc`): done

**The number.** D22 (CPU, one core, worktree `w-inc-I55`, log `review/incompat/I55/harness1.log`), one
sample each, by a harness doing exactly the computation of the two new slow tests: zincblende AlAs at
`ecutwfc = 4`, `ecutrho = 32` (smooth grid 9^3, dense 15^3), Gamma and a general point, `eta = 0.01` Ha,
the field along x, at 0.02, 0.05 and 0.11 Ha.

- Against `dense_first_order` on the same two-grid cell (the states placed in the dense box by Miller
  index, `v(G - G')` read off the dense transform, so nothing of the interpolation is shared):
  **1.9e-11 to 5.1e-11** relative with the Hartree kernel and **9.5e-12 to 2.5e-11** with `'hxc'`, in 9
  to 12 outer GMRES products; the frozen current 2.6e-13 to 9.2e-13. The update moves the current by 2.1
  to 11.5 per cent (Hartree) and 0.08 to 2.1 per cent (`'hxc'`), so it is load-bearing. Asserted at 1e-9,
  1e-11 and 5e-4, the one-grid test's tolerances. These are the figures of the one-grid test
  (`test_the_self_consistent_first_order_is_the_dense_one`, 9e-12 to 5e-11).
- The entry's identity, two grids against one grid with the same states, energies and potential (the
  potential resampled onto the one-grid cell, whose 9^3 grid is the two-grid cell's smooth grid, and the
  wavefunction spheres checked to hold the same Miller indices in the same order): with the Hartree
  kernel **1.8e-14 to 3.5e-14** relative, asserted at 1e-9.

**The entry's check is half wrong.** "The two-grid run equals the one-grid run to round-off" holds for
the Hartree kernel, which is diagonal in `G`, and not for `'hxc'`: there the two runs differ by **2.0e-6,
4.4e-6 and 1.5e-5** at the three frequencies, because `f_xc drho` is a pointwise product formed on the
dense grid in one run and the smooth grid in the other, exactly as the ground state's `v_xc` differs
between them. That the difference is aliasing and not a bug is the dense reference's 1e-11 above, which
uses the dense grid throughout. So the check for `'hxc'` is the dense reference, and the identity is
asserted for the Hartree kernel only.

**What was missing.** The entry named one direction, the dense-to-smooth interpolation of `dv`. The code
needed both and a change of where the unknown lives: `_orders_at` applies `dv_+` and returns the cross
density on the smooth grid (`chunk.template.grid` is `basis.smooth.grid`), while the GMRES unknown, the
`cross` accumulator and the kernel were dense-shaped. Now `dv_+` and the cross density are on the smooth
grid, and the kernel takes each real part `to_dense` (a zero-pad in `G`, exact for a product of two states)
-> symmetrise -> `kernel_real` on the dense grid -> `to_smooth` (keep the smooth sphere, which is what
`local_terms` does with the ground-state potential) -> drop the uniform part. The real and imaginary parts
go separately because both interpolations return `jnp.real`. `realtime/dense.py:dense_first_order` lost
its own one-grid guard, which was a deletion: it never touched the smooth grid. On one grid both
interpolations are the identity, so the one-grid path is unchanged.

**The guard** in `hierarchy_linear_self_consistent` is deleted, not narrowed: the only other datasets
with two grids are ultrasoft and PAW, and `require_a_potential_mode` refuses them before it. Siblings
asserted in `tests/unit/test_hierarchy_two_grids.py` (fast, 21 passed with the realtime unit files and
`test_realtime_regimes.py` under `-m 'not slow'` on D22, `unit1.log`): an ultrasoft dataset on two grids is
refused with both `'hartree'` and `'hxc'`, and a meta-GGA with `'hxc'`. The guard was seen to fire on
`si2-nc-dual8.in` before the change; that test is now `test_two_grids_pass_the_guard_that_refused_them`,
which only says the grid message is gone (the call stops later on placeholder arrays), so the measurement
is the slow tests.

**Not measured on two grids**, though the code path is shape-agnostic: a symmetry-reduced k-set with
`density_symmetry` (AlAs runs `nosym`; the density goes `to_dense` and is symmetrised on the dense grid,
the propagation's order), a `k_batch > 1` chunk (the D22 slot ran the CPU's `k_batch = 1`), a collinear
`nspin = 2` run and a magnetic spinor (`to_dense`/`to_smooth` act per component on the leading axis). The
one-grid Sternheimer-shift test covers the wedge on one grid only.
