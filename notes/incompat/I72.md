# I72. Residual (Newton) solver x spin spiral: done (NC, US, PAW), with a Hubbard U and a meta-GGA still refused

**The number.** Harness `review/incompat/I72/harness.py` on D22 (CPU, one core, `w-inc-I72` at da44fe3, the same code as the final commit, log
`review/incompat/I72/harness-1.log`), one sample per cell: `run_scf` with the mixing loop against
`scf_solver = 'newton-krylov'` (`forcing = 0.5`, `warmup = 6`, finite-difference Jacobian, Kerker), both
at `conv_thr = 1e-9`, `mixing_beta = 0.3`, from the same atomic start. The identity checked is that two
solvers of `rho = F(rho)` land on the same fixed point, to `conv_thr`.

`dr2` of the difference is the loop's own measure (`scf_accuracy_split`, Hartree weight on the charge,
constant weight on `m`), asserted below `10 conv_thr`; the energy at `TOTAL_ENERGY_RY = 1e-6`. The moment is
asserted against the Cauchy-Schwarz bound that `dr2` puts on it,
`V sqrt(10 conv_thr / (V/2 x 8 pi/(2 pi)^2))` = 4.8e-3 on these cells: the hydrogen chain's 4.5e-4 is
inside it and outside a naive 1e-4, which is the stopping rule's looseness on `m` and not a different
state (both runs individually at `dr2` 2.3e-10 and below 1e-9). `_weights` (the residual's traceable
occupations) against `Calculation.occupations` on the converged spiral eigenvalues: 0.0 on all three.
Wall time: Newton 3.9, 20.4, 19.4 s against mixing 3.5, 10.7, 11.9 s, first calls included, so not a
timing claim.

**What was missing** (the entry said "unread"). For a norm-conserving, ultrasoft or PAW spiral,
nothing in the map. The guard was one line with no reason, and every call in `ScfResidual.step` is the
mixing loop's own `Calculation` method (`potential`, `onecenter`, `hamiltonian`, `diagonalize`, `becsum`,
`density`); the spiral lives inside them (the two spheres at `k +- q/2`, the rotated-frame density,
`_addusdens_spiral`'s displaced table). Three things that could have differed were read and are
consistent: the real-space `kerker_preconditioner` at `nspin_mag = 4` screens channel 0 only and gives `m`
the plain `beta` (`defuqumat/scf/mixing.py:950-953`), so the transverse pair on the displaced sphere is
never cut (unlike I74's G-space mixing); `accuracy_of` is `scf_accuracy` on the resident dense sphere, the
same as the loop's `dr2`; and `_weights` and `Calculation.occupations` both take the unshifted
`system.kpoints.weights` with the eigenvalues per unshifted k. The guard is deleted
(`defuqumat/scf/residual.py:make_residual`).

**Under a Hubbard U the map is not the loop's, and that is a packing defect, not a spiral term.** A
spinor `ns` is complex. The mixing loop carries it as real and imaginary pairs (`driver._pack_ns`, viewed
through `_ns_dtypes`), while `ScfResidual.pack` casts it with `dtype=float` and `ScfResidual.flatten`
takes `jnp.real(ns)`, so the residual's state keeps only the real part. Measured on D22
(`review/incompat/I72/fixpoint.py U`, log `fixpoint-U.log`, worktree `w-inc-I72-v2`, one sample) on
`nii-chain-spiral.in` with `HUBBARD {atomic}` U Ni-3d 4.0 eV: `ns` is complex128 of shape (4, 1, 5, 5)
with max abs(Im ns) 4.5e-2 against max abs(Re ns) 0.94; at the mixing loop's converged state (29
iterations, last accuracy 8.9e-10) the residual's `accuracy_of(F(x*) - x*)` is **2.34e-4** (ns part
1.56e-5), while the same calls with `ns` handed over complex read **2.3e-8** (ns part 2.0e-9). So the real
part is the whole discrepancy. The misleading symptom is a `ComplexWarning` at `pack`, which a harness
running under `warnings.simplefilter("ignore")` never shows. The verifier's Newton run on the same cell
(`review/incompat/I72ver/ver2.py`, `ver2.log`) converged on its own to `solver.accuracy` 1.7e-10 and
landed dE = -7.3e-3 Ry, dr2 3.2e-2 and d int abs(m) = -0.11 from the mixer, the fixed point of a different
map. A spiral with a U is refused by name in `make_residual`, before any array is built. The defect is not
spiral-specific: a non-spiral noncollinear run with a U goes through the same packing at master
(126d6ec), and no test runs `newton-krylov` on one. That regime is not refused here, since it is outside
I72; it is a finding for the integrator (an `OPEN.md` candidate). The fix is to carry the real and
imaginary parts in `pack`, `unpack` and `flatten`, with the real dtype read off `ns` as `_ns_dtypes`
does, and its check is the fixed-point residual above falling to the loop's accuracy, then a Newton run on
the cell (672 s on one D22 core for the verifier's), so a slow test.

**Under a meta-GGA it is not measured.** The verifier's run of Newton on `h-chain-spiral.in` under `tb09`
and `noncollinear_gga = 'kubler'` (`review/incompat/I72ver/ver1.py D`, `ver1-DE.log`) had printed nothing
after 42 minutes of CPU on one core (read at 19:57 on 2026-10-16, still running; the integrator can read
the log once it ends, and a clean number there is what lifting this refusal needs, with a slow case), where the same cell without the meta-GGA does both solvers in 7 s.
`tau` is real, so the packing defect above does not apply, but with no number the regime stays refused by
name in `make_residual`.

**Trap list, corrected in the fix round.** The first version of this record said that only "a check whose
null cannot be told from a pass" applied and that it was handled. That was wrong twice. First, the slow
test compared the mixer with the mixer: `run_scf` hands the Newton state to the mixing loop, which
iterates with its own methods until it converges, so the final states agree whatever map Newton solved.
The verifier patched `ScfResidual.step` to scale the output `m_x, m_y` by 0.97 (`ver1.py C`): Newton
converged to that map's fixed point, the loop took 10 more iterations against 1 in every genuine run, and
all of the old assertions passed (dE -5.7e-9 Ry, dr2 6.5e-9, d int abs(m) 6.8e-4). This is "a method that
could not have returned a surprise proves nothing by finding none", and "a confirming number counts only if
the alternative hypothesis would have read differently". The test now asserts what does read differently:
`newton.solver.converged`, `newton.iterations == 1` (1 on all three cells in `harness-1.log`, 10 for the
scaled map), and the residual's own `F` at the mixer's converged state, `accuracy_of(F(x*) - x*) < 10
conv_thr`, which is path-independent: **1.32e-10, 2.70e-10, 1.35e-11** on NC, US and PAW
(`fixpoint-N.log`, one sample each, against the loop's last 2.45e-10, 7.32e-10, 1.34e-10), against
**3.32e-6** for the scaled map (`review/incompat/I72ver/ver3.log`). Second, "nothing in the map" was false
under a Hubbard U (above), which is the trap "inherit a refusal only after checking which machine it
belongs to" in reverse: the old guard covered a packing defect that has nothing to do with the spiral. The
dr2 between the two final states is now bounded at 100 conv_thr rather than 10, since it is the stopping
residual magnified along a soft magnetic direction: with `warmup = 0` it read 1.28e-8 (magnetic part
1.05e-8, d int abs(m) 9.5e-4) with both solvers converged and the loop at one iteration (`ver1-AB.log`),
and the earlier 2.96e-9 at `warmup = 6` was a margin of 3 on one sample. The moment stays against the
Cauchy-Schwarz bound at 10 conv_thr, 4.8e-3, which the `warmup = 0` 9.5e-4 is inside. The verifier's part
B (`spiral_q = 0.35`, 1x1x6 mesh, Kerker off, `warmup = 3`) read 1 loop iteration, dE 9.5e-10, dr2 2.4e-9
and fixed-point residual 1.6e-11. The diff touches no differentiated path, dtype or k loop.
