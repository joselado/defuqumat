is polarized by its own `starting_magnetization`. Two controls on the same seed make it

with `m = 0` it stays unpolarized at +1.350e-4 Ry above the ferromagnet. So the
magnetization the seed carries is what decides the fixed point.

## What was missing, as found

The entry said "a transfer rule for the magnetization". The rule is short: Elk's
collinear `magmt`/`magir` is `m_z = n_up - n_down` in e/bohr^3 with no g-factor, the
object `Calculation.starting_density` builds, so the seed is
`(up, down) = (rho + m, rho - m) / 2`, with `m` taking the charge's renormalisation factor
so `zeta` is Elk's at every point. What the entry did not say:

- **The reader stopped at `vsir`**, and the magnetic records are three more
  one-record pairs (`writestate.f90:84-108`) with `ndmag` slowest on both halves, the third
  (`bsmt`) on the **coarse** radial mesh `nrcmtmax`. All three are read and length-checked;
  `bxc`/`bs` are energies and take the Hartree factor. No consumer reads them.
- **The reconstruction hard-coded `rhomt`/`rhoir`.** `ElkState.magnetization_component`
  returns the state with a magnetization component in the density's place, and
  `elk_density._on_grid` is the old body of `density_on`, so the moment goes through the
  same `rfpts` route Elk's own `vecplot` uses, with nothing reimplemented.
- **A spiral cannot be told from a noncollinear state at read time**: `STATE.OUT` records
  neither `spinsprl` nor `vqlss`. That is why `ndmag = 3` stays refused rather than mapped
  onto `nspin = 4`, and the message says so.
- **There was no spin-polarized fixture.** `h_sc_spin` is new. At `a = 4` bohr Elk
  converges to -0.044, at 6 it cycles for 200 iterations, and with `reducebf = 0.5` the
  field is gone before the moment forms and the mixer lands on the unpolarized fixed point.

Still refused, by name: `ndmag = 3` (and spirals) at read time; `fsmtype != 0` at read
time (the conservative call: the moment is the constrained one and `bfsmc`/`bfsmcmt` are
trailing records; whether to seed from it anyway is a question for the user); a polarized
state into `nspin_mag = 1` ("silently drop the moment"); an unpolarized state into
`nspin_mag = 2` (the old refusal, its slow test unchanged and passing on the new message);
anything into `nspin_mag = 4`. DFT+U, a fixed tensor moment and a core are untouched.

**A false alarm found on the way, not fixed (and not new).** `run_scf` warns that the
Elk seed is not invariant under the 48 operations, at 2.68e-2 for the charge and 2.87e-2
for the magnetization. It does the same on master's `h_sc` seed (2.24e-2). The residual
is exactly the part of the seed outside the dense G-sphere (2.24e-2 and 2.71e-2 by norm):
projected onto the sphere, the seed's residual is 6e-16 and 9e-16. It is the muffin-tin
cusp sampled pointwise into the box corners, which the run drops anyway. A projection in
`density_on` would silence it; that is a decision for the integrator.

## Guide and README

`docs/guide/elk-seed.md`, Limits. Replace

> A spin-polarized Elk state and a spin spiral give an error, because the
> magnetization is a second field, and a seed without it would start a magnetic
> run from a non-magnetic density. A run that carries a magnetization, with
> `nspin=2` or noncollinear, gives an error for the same reason.

by

> A collinear spin-polarized Elk state can start a run with `nspin=2`. The code moves
> the charge and the magnetization of Elk to the grid. Both are scaled by the same
> factor, so the polarization at each point is the one of Elk. A noncollinear Elk
> state gives an error. This includes a spin spiral, because `STATE.OUT` does not say
> that the run was a spiral. An Elk state with a fixed spin moment also gives an
> error. A spin-polarized Elk state with an `nspin=1` run gives an error, because the
> moment would be lost. An unpolarized Elk state with an `nspin=2` run gives an error,
> because the seed would have no moment. A noncollinear run gives an error with any
> Elk state.

`README.md`, feature table, row "**Starting from an all-electron ground state**³": no
change. The row has no ticks, and footnote ³ (`docs/reference-codes.md`, note 3, "blank in
