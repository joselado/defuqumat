# I37. Velocity operator `dH/dk` x gamma-only storage

Status: **done for the band velocities and the matrix elements**; the consumers
that build their operator inside a compiled walk over k-chunks (the optical
conductivity and the Kerr angle, second-harmonic generation, the shift current)
still refuse, with a sharper message.

`1.8e-15` (the refusal's own measurement). The check is the identity named in the
entry, the same cell at an explicit `k = 0` on the whole sphere; it is a pair of
single runs, not a median, since both sides are deterministic on one core.

Test: `tests/regression/test_gamma_only.py::test_the_velocity_operator_unfolds_gamma_storage`
(slow, as the test it replaces was), asserting the zero velocities on both
storages, the block norms and `Tr(v_a v_b)` to 1e-10 with the largest block above
0.5, and that the three remaining refusals fire. Run on D22 (`run2.log`) with
`test_velocity_locality.py`, `test_sibling_refusals.py` and
`test_effective_mass.py`: 52 passed. Measured on the tree of commit `f6fcf6d`
(since squashed into this one); one change landed after it, in `whole_sphere`'s
map, which now records the slot of each stored plane wave in the padded array
rather than its rank among the unmasked ones. The two are the same for a prefix
mask, which every gamma calculation has (one k-point, so `npwx = npw` and the
mask is all true), so the numbers above cannot move.

Trap check run against the diff: no `abs`, no band diagonal added (the band
velocities keep their multiplet blocks), no k-set constructed (the k = 0 list is a
`dataclasses.replace` that keeps `spin_normalized`), no hardcoded dtype, no walk
over k, `np.asarray` only on the host-side plane-wave indices and mask, and the
alignment between the two spheres is by Miller index.

## What was missing, and where the entry's term was wrong

The entry says "the stored half needs its own rule". That rule exists, and it is
`2i Im(sum_half) - (G = 0 term)` for the tangent, because `dc(-G) = -conj(dc(G))`
for a real state, but it is not a local fix: the `jvp` passes through every
gamma-packed kernel (`calbec_gamma`'s `2 Re(sum) - G0`, the local term's
conjugate fill) and each would need its own rule for a tangent of the opposite
parity, and the second derivative flips it back. What was actually missing is
smaller: an unfold. `response/velocity.py:whole_sphere` builds
`calculation.at_kpoints` at the same `k = 0` with the half-sphere flag dropped
(every k-independent array shared, only the sphere, `|k+G|^2` and `vkb`
rebuilt) and a map from each whole-sphere slot to its stored plane wave, aligned
by Miller index on the shared smooth set, with a conjugation flag for `-G`.
`VelocityOperator` uses it on construction for a gamma-storage calculation, and
`_tangent`, `_second_tangent` and `band_velocities` unfold the states on entry
(`jnp` gather, so a derivative through the states survives; idempotent by width).

Refusals that stay, each with its own message:

- `Calculation.at_kcart` on the half sphere (`scf/driver.py`), now reached only by
  a direct call; its message names `VelocityOperator` as the route.
- `VelocityOperator.apply`, `apply_s`, `both`, `apply_second` and `projectors`
  under gamma storage: their output is as wide as the sphere and the whole-sphere
  `dH/dk|psi>` has no half-sphere form a caller could contract with
  `2 Re(sum) - G0`. The Sternheimer stack (`chunked.py`, `efield.py`) is the
  consumer of these, and a field response refuses gamma storage before it reaches
  them (`response/sternheimer.py:1572`, unless `gamma_ok`; `efield.py:358`).
  Those consumers were not run here.
- An operator built inside a compiled walk over k-chunks (`with_rows` hands it
  traced rows, so the sphere cannot be rebuilt on the host). Measured on D22
  (`run1.log`, `run3.log`): `get_optical_conductivity`, `get_shift_current` and
  `get_shg` all raise this `NotImplementedError` under gamma storage, while the
  whole-sphere runs complete. Lifting them needs the whole-sphere twin built once
  on the host by the consumer and handed to each chunk's operator; that is a
  second change with its own number per consumer.

The old guard's comment listed the nesting function among the consumers of
`dH/dk`; it is not one (`workflows/nesting.py` and `response/nesting.py` never
build a `VelocityOperator`).

## User guide

Page `docs/guide/ground-state.md`, the "Limits" note of the gamma storage. Replace

> The velocity operator gives an error too, and with it the band velocities, the
> optical conductivity, the Kerr angle, second-harmonic generation, the shift
> current and the nesting function.

with

> The band velocities work on the half sphere, because the code copies the states
> onto the whole sphere before it takes $\partial H/\partial\mathbf k$. The optical
> conductivity, the Kerr angle, second-harmonic generation and the shift current
> still give an error.

(The nesting function is dropped from that sentence because it never used the
velocity operator; whether it runs on the half sphere was not checked here, since
the silicon cell has fixed occupations and the nesting function refuses those
first.)
