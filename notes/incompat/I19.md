# I19. Nesting function x constrained `tot_magnetization`: done

Branch `incompat/I19`. The refusal is lifted for a smeared (or tetrahedron, with
`degauss` passed) run with a constrained moment; a `tot_magnetization` run with fixed
occupations is still refused, now by the fixed-occupation guard.

## What was missing

The entry says `N(q)` "resolved by channel pair at two Fermi levels". That was not what
the code lacked. The `nspin = 2` nesting function was already defined as the correlation
of the *total* weight `g = g_up + g_dw` (the union of the two channel surfaces, with
cross terms), and the two-level case is the same object with each channel's delta at its
own level, so no channel-pair resolution is needed. What was missing was in two places:

- `defuqumat/response/nesting.py:fermi_surface_weights` took one scalar level for every
  channel. It now takes a scalar or one level per channel (`channel_levels`,
  `channel_weights`), and refuses a level count that is not the channel count rather than
  broadcasting it against the band axis;
- `defuqumat/workflows/nesting.py:run_nesting` read `nscf.fermi_energy`, which on a
  `two_fermi_energies` run is QE's printed *mean* of the pair. Lifting the guard alone
  would have built `g` at a level neither channel sits at, with the sum rule still closing
  against its own wrong `D(E_F)`. It now reads `(fermi_energy_up, fermi_energy_down)`, and
  refuses a scalar `fermi_energy=` on such a run (and a pair on a one-level run).

`NestingFunction` carries `fermi_energy_up` and `fermi_energy_down` beside the scalar,
which is the mean in this regime.

The guard `require_a_fermi_surface` lost its `tot_magnetization` branch. The fixed-occupation
case (`o2-fixed-lsda`) is caught by the fixed-occupation refusal, whose message now names
the smeared case as accepted; `test_it_refuses_two_fermi_levels` asserts that refusal
(`match="never searches for a level"`), and `test_a_smeared_constrained_moment_is_accepted`
is its complement. The spiral and fixed-occupation refusals still fire.

## User guide

`docs/guide/scattering.md`, the Limits note. Replace

> The nesting function gives an error for a run with fixed occupations
> (`occupations = 'fixed'` or `'from_input'`), which has no Fermi level, and for
> a run with `tot_magnetization`, which has one Fermi level for each spin
> channel.

with

> The nesting function gives an error for a run with fixed occupations
> (`occupations = 'fixed'` or `'from_input'`), which has no Fermi level, also
> when it has `tot_magnetization`. With a smearing, a run with `tot_magnetization`
> has one Fermi level for each spin channel, and the delta function of each
> channel is then at its own level. In that case `fermi_energy` must be the pair
> `(ef_up, ef_dw)` if you give it, and the result has `fermi_energy_up` and
> `fermi_energy_down`.

The keyword list in the same section could also say, under **`fermi_energy`**: "For a
run with `tot_magnetization`, this is the pair of the two levels."
