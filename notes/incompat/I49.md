# I49. Real-time propagation with the field's little group x shifted Monkhorst-Pack grid

Status: done. A shifted grid is now reduced by the members of the field's little group that
map the grid onto itself, and the wedge reproduces the whole shifted grid to 1.4e-8 at a
frozen potential and 1.7e-8 with the potential updated. The two sibling refusals of a
reduced k-set stay and each has a test.

**Where the alternative reads differently.** With the whole eight-operation little group,
`irreducible_wedge` skips the off-grid images silently and the current is averaged over
operations the grid does not have. At a frozen potential the longitudinal `J_x` is
invariant under all eight operations, so the eight-operation average leaves it unchanged
(8.67e-9 in both arms) and only the transverse components separate the two, at 0.82 of
the scale. With the potential updated the wrong density completion moves `J_x` too, by
3.3e-2. A check reading `J_x` alone at a frozen potential could not have told the fix from
the bug; the test compares all three components.

**The floor** of 1.4e-8 is the fixed-density solve's default threshold, not round-off: the
two arms re-solve 64 and 40 points separately (I39's same-points identity reached 1.8e-13).
The regression test asserts `1e-6 * scale`, with the measured value 70 times below it.

**The control.** At `126d6ec` the guard is `workflows/realtime.py:174`,
`if little_group and any(shift)`; on the old base the new tests fail against it with
`NotImplementedError: the little group of the field on a shifted Monkhorst-Pack grid is
not implemented` (`/l/ladovj1/review/incompat/I49/verify/rev.log`, the code reverted, the
tests kept).

## What was missing

The entry's term is right: a shifted grid is not closed under the point group, nor under
the field's little group. What was missing is the subgroup that the grid is closed under.
`kpoints.grid_stabilizer` returns which operations map every grid point onto a grid point,
and `workflows/realtime._grid_little_group` keeps those members of the little group,
with their fractional translations. They form a group, the stabilizer of a set, and the
identity is always in it (asserted). The wedge, the current's polar-vector average and the
density's completion for `potential = 'hartree' | 'hxc'` all take this subgroup, so the
wedge sums exactly what the whole grid sums. `_kset_with_storage` now builds the reduced
set at the run's own shift instead of `(0, 0, 0)`.

Two side effects. An unshifted grid with unequal divisions (say `4 4 2`) is not closed
under every operation either, and the old code handed it the whole little group with the
same silent skip; it now gets the stabilizer as well. Not measured separately. And an
explicit `grid=` still builds an unshifted grid, as before; a shifted grid is reached only
through the ground state's own `K_POINTS`. This is deliberate and the docstring says so.

**What the user should know.** On fcc silicon the shifted `4 4 4 1 1 1` grid is not cubic,
and its own k-sum carries a transverse current the crystal forbids: for a `[100]` field,
`max |J_y| = max |J_z| = 2.6e-4` a.u. against `max |J_x| = 3.2e-4` (on `3 3 3 1 1 1` the
transverse part is larger than the longitudinal one), where the unshifted `4 4 4` gives
`J_y = 0` exactly. The fix reproduces the shifted grid's answer exactly, which is the right
identity, but that answer carries the grid's broken symmetry. For a cubic cell an unshifted
grid stays the better choice.

Trap-check against `git diff master`: the new code is host-side NumPy (no differentiated
path, no dtype, no k walk); the k-set from `KPoints.automatic` still goes through
`for_spin`; the current is linear in a per-k polar vector, so the wedge sum completes
under the kept group. Nothing found.

## User guide

`docs/guide/nonlinear.md`, Limits note. Replace

> A shifted mesh gives an error, because it is not closed under the point
> group, and `little_group=False` propagates the whole shifted mesh instead.

with

> A shifted mesh works. It is not closed under the point group, so the code
> keeps only the operations that map the mesh onto itself. For silicon on
> `4 4 4 1 1 1` with a field along [100], that is two of eight, and 40 of 64
> points. The result is the same as `little_group=False` to 1e-8. Note that a
> shifted mesh on a cubic cell is not cubic, so it gives a small current
> across the field that the crystal does not have. For a cubic cell, use an
> unshifted mesh.
