# I70. Elk `STATE.OUT` seed x DFT+U or a fixed tensor moment: done for DFT+U, the fixed tensor moment kept refused

**The number.** Harness `review/incompat/I70/harness.py` on D22 (CPU, one core, `w-inc-I70`, log
`review/incompat/I70/run1.log`), one sample, the same computation as the slow test below. Elk 11.0.2 run
on simple cubic hydrogen (`a = 3.0` bohr, `4x4x4`) with `dft+u` `dftu = 1`, `U = 4` eV on 1s
(`tests/data/elk/h_sc_dftu/elk.in`, converged in 0.3 s), then the defuqumat DFT+U SCF on the same cell
with `U H-1s 4.0` (`h_sc_dftu/scf.in`, `conv_thr = 1e-10`), once from the Elk density and once from the
atomic superposition. **`dE = -6.7e-16` Ry, `max|drho| = 7.0e-9` e/bohr^3, `max|dns| = 5.3e-9`**, five
iterations each, `E = -1.04261921377815` Ry both. That this could have failed: the same cell without `U`
is 3.756e-2 Ry lower and its density 3.9e-4 away, so a seed that moved the run off the Hubbard fixed point
would show at that scale.

The reader on the genuine file, against Elk's own printout (fast, `tests/unit/test_elk_reader.py`):
`vmatmt[0,0]` = 0.033063722214 Ha against `VMATMT.OUT`'s 0.3306372221E-01 (inside half a unit of its
last printed digit), the other 255 entries exactly zero, and `chgmt = 0.6054875069`,
`chgir = 0.3945124931` against `INFO.OUT` at 1e-8, so the four pairs in front of the new record are read
as before.

**What was missing, and where the entry was wrong.** The entry said "reading the trailing occupation and
potential records". There is no occupation record: `writestate.f90:122-125` writes `vmatmt`, the Hubbard
*potential* matrix in Elk's muffin-tin `lm` basis, and `vmftm` only for a fixed tensor moment
(`:127-129`); Elk rebuilds `dmatmt` from its states after `readstate` (`gndstate.f90:194-201`), and
`DMATMT.OUT` (0.5501448706 here) is a separate file. Neither matrix can seed this code's `ns`: it is in
Elk's radial functions, and this run's Hubbard projectors are the pseudo-atomic orbitals. So the change
is (1) `read_elk_state` consumes the record, one complex
`(lmmaxdm, nspinor, lmmaxdm, nspinor, natmtot)` in Fortran order (`readstate.f90:251`), its length
asserted, in Ry on `ElkState.vmatmt` (`None` without DFT+U); (2) the meta-GGA pair `wxcmt, wxcir`, which
`writestate.f90:112-119` writes *before* `vmatmt`, is now consumed under `xcgrad in (3, 4, 5, 6)`. The
reader never read it before, which was harmless only because nothing was read after `vsir`; without
it a meta-GGA DFT+U state would have taken the `wxc` pair as `vmatmt` (the synthetic test fires the length
check that way); (3) `density_on` warns, for a DFT+U state, that only the density crosses and that `ns`
starts from this run's own `starting_ns` (or, for a run with no Hubbard term, that it converges to the
plain functional). The seed itself was already right. The density pairs come before the trailing record,
so a DFT+U state's density was always read correctly, and the read-time refusal was the only obstacle.

**What stays refused, and why.** `ftmtype != 0`, by name, at read time, with a sharpened message: a fixed
tensor moment is a constraint on Elk's functional (`vmftm`) that this code does not implement. A genuine
file of that kind cannot reach the guard, because Elk stops on tensor moments without spin-orbit coupling
(`init0.f90:239-247`) and spin-orbit coupling switches `spinpol` on (`init0.f90:126`), so the spin guard
fires first; the guard is kept for a synthetic or a future file. Tests: the parametrized refusal test now
has `ftmtype = 1` and `ftmtype = 1, dftu = 1` rows (both "tensor moment") beside the `spinpol` and
pre-2.0.0 rows, all firing. Not changed: a spin-polarized state, a core, a fixed density.

Pre-existing and not changed: the Elk density on the FFT grid is not invariant under the 48 operations
(`||rho - sym(rho)|| / ||rho|| = 2.2e-2`, the run's own warning, seen on the DFT+U seed). It comes from
the seed route (the muffin tin written pointwise onto the FFT grid), not from `U`; whether the `h_sc`
seed without `U` gives the same figure was not measured here. The first iteration averages it away.

**User guide**, `docs/guide/elk-seed.md`, "Limits" note, second paragraph. Replace the sentence "A DFT+U
state, or one with fixed tensor moments, also gives an error, because the code does not read their
occupation matrices." with: "A DFT+U state works as a seed. `STATE.OUT` does not contain the occupation
matrix of Elk, so only the density is used, and the code gives a warning. The Hubbard occupations then
start from `starting_ns` of the run, as in a normal DFT+U run. A state with fixed tensor moments gives an
error, because the code does not have this constraint."
