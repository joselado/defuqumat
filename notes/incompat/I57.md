**What was missing, and where the entry was wrong.** The entry said "`kpoint_grid_efield` and the string
set it builds". The semantics were the missing piece: in `pw.x` an automatic grid under `lelfield` **is**
`l3dstring`, and then the field is read from `efield_cart` (projected as `efield_cry`), while `efield` and
`gdir` are not read at all (`h_psi.f90:276`, `c_bands.f90:967`, `calc_pol` in `electrons.f90:1608`;
INPUT_PW: `efield_cart` is "used only if lelfield and if k-points are automatic"). So the input this code
used to refuse, an automatic grid with `efield` and `gdir`, is a **zero-field** run in `pw.x`. What is
implemented is the case that is the `gdir` form exactly: `efield_cart` along one Cartesian axis of a cell
whose other lattice vectors have no component along it (then `efield_cry` and `transform_el` are the
identity on that axis and the two other operators carry zero field). The builder
(`system/builder.py:_berry_strings_as_a_list`) writes the grid out as `kpoint_grid_efield`'s points, in
`nx_el(:, gdir)`'s order, as a `crystal` list with equal weights, and the rest of the run is the
explicit-list run.

**What stays refused**, each with its test in `tests/unit/test_berryfield.py`: an automatic grid with
`efield_cart = 0`, which `pw.x` runs as a zero field with three string sets
(`test_an_automatic_grid_without_efield_cart_is_refused`); `efield_cart` along more than one axis, the real
`l3dstring` with three operators (`test_efield_cart_along_two_axes_is_refused`); an axis another lattice
vector has a component along (`test_efield_cart_on_an_oblique_axis_is_refused`); and `efield_cart` with a
manual list, which `pw.x` ignores (`test_three_directions_are_refused`, whose message now says so); and an
axis whose lattice vector points against it, where `efield_cry` would flip the sign
(`test_efield_cart_against_a_reversed_axis_is_refused`).

**User guide**, `docs/guide/electric-field.md`, "Limits" note, second paragraph. Replace

> `efield_cart` (the field in three directions) and an automatic k-mesh, which `pw.x` turns into that
> form, give an error, so you give the strings as an explicit list of k-points with `gdir` and `nppstr`.

with

> With an automatic k-mesh, `pw.x` reads the field from `efield_cart` and ignores `efield` and `gdir`.

> mesh with `efield_cart` zero, which in `pw.x` is a run with no field.
