# I52. Every `Calculator.get_*` beyond SCF, forces, stress and relaxation, and the response stack x k-point pools: partial

Three getters are lifted, `get_bands`, `get_nscf` and `get_dos`, with a number; the other 57 `get_*`
still refuse by name under pools, and so does `response/efield.py`.

**The number.** D22, CPU, one slot (one core), worktree `/l/ladovj1/w-inc-I52-t2` at `e463b04`, log
`/l/ladovj1/review/incompat/I52/run3-harness.log`, one sample, harness
`/l/ladovj1/review/incompat/I52/harness_r2.py` doing the computation of the slow tests below outside
pytest. Silicon, 2x2x2 `nosym` grid (8 k-points), SCF at `conv_thr = 1e-12`, then a 7-point band path,
an NSCF on the SCF's own 8 points and a DOS on a 27-point grid, all at `nbnd = 8`; one pool against two
and three, the identity being that the pool count is invisible beyond round-off:

| quantity | 2 pools | 3 pools |
|---|---|---|
| band path eigenvalues, max abs (Ry) | 1.1e-14 | 7.3e-15 |
| NSCF eigenvalues | 8.7e-15 | 1.1e-14 |
| DOS-grid eigenvalues | 1.2e-14 | 1.3e-14 |
| NSCF HOMO, DOS HOMO, DOS LUMO | 3.1e-15, 3.3e-15, 3.0e-15 | 1.7e-16, 3.3e-16, 1.0e-15 |
| DOS energy axis | 1.3e-15 | 2.2e-16 |
| DOS curve, max abs / its peak (901.5) | 1.6e-12 | 1.9e-12 |

Every rank returns the same arrays (checked at three pools), and under real pools `get_pdos` refuses
by name on every rank. **The guard fires**: a gather that drops the layout (rows put back as contiguous
blocks; at three pools the longest-first layout is `[[0, 4], [2, 6], [1, 3, 5]]`, not
`[[0, 1, 2], [3, 4], [5, 6]]`) moves the band path by **0.99 Ry**. The facade check (57 of 64 `get_*`
wrapped, exactly the complement of `POOL_AWARE`; `get_pdos`, `get_dielectric_tensor` and
`get_polarization` refuse) passes in the same harness. The non-slow tests of
`tests/unit/test_parallel.py` and `tests/unit/test_calculator.py` pass on the same head (55 passed,
`run4-fast.log`).

**What was missing.** The entry says "a pool-aware reduction in each workflow". For these three that is
wrong: nothing is reduced, since a fixed-density solve is independent per k-point. What was missing was
solving each pool's own rows and gathering the eigenvalues with the layout. `fixed_density_states`
(`workflows/nscf.py`) now, under pools and with `keep_states = False`, takes the SCF's longest-first
layout (`_k_costs`), solves its rows through `stream_eigenvalues(rows=...)` (each row addressed by its
global index on the whole set's tables, so starting vectors, sphere and Davidson cap are the one-pool
run's), and gathers with `Pools.gather_k(layout=...)`; the occupations, the HOMO/LUMO and the DOS curve are
then built on the whole set by every pool. Three cases are not split but solved whole by every pool, which
is the same answer at the one-pool cost: a caller keeping the states, `kcart` (the effective mass), and a
k-set with fewer points than pools. Note the asymmetry with the SCF, which refuses "2 pools for 1
k-points".

**What stays refused, and what each needs.** Every getter that reads the wavefunctions (`get_pdos`, the
response stack, the invariants, the magnetism tail) needs either the states gathered or a reduction of a
per-k sum over the pools, read workflow by workflow; none was read here.

**A harness defect found on the way, fixed.** The old implementer's second D22 run (on the old base)
aborted with `Shutdown barrier has failed ... # of tasks that reached the barrier: 1/2`, exit -6, which
reads like a pools bug. It was `_start_pools` in `tests/unit/test_parallel.py`, which drained only the
rank it was waiting on: the pooled script's JSON is 76 kB (measured, with the DOS energy axis added),
past the 64 KiB pipe buffer, so a later rank blocked in its write and never reached the shutdown
barrier. The ranks now write to files.
