# I62. Transverse spin susceptibility (magnons) x `nosource`: blocked (behind I59's texture, and a tensor kernel)

**No number, and none is possible yet.** The guard was **unreachable**: `refuse_source_free`
(`scf/sourcefree.py`) refuses `nosource` without `noncolin`, and `require_a_transverse_regime` refused every
noncollinear run before reaching the `source_free` branch. The branch is now asked ahead of the
noncollinear block and fires on `ni-noncol-111-nosource.in`
(`tests/unit/test_magnon_regimes.py::test_nosource_is_refused_for_its_own_reason`, which also asserts
`calculation.source_free`).

**Why blocked, and that it is a missing term rather than physics.** Even the case I59 now admits, a
collinear moment along z run as a spinor, does not survive the projection: removing the longitudinal part
of `B_xc z` adds `x` and `y` components wherever `d_z B_xc != 0`, so the projected field is not parallel
to `m`, the ground state is a texture, and I59's collinear-channel check would refuse it anyway. What is
missing is the 4x4 response of I59 plus a transverse kernel that is a tensor, `dB_xc,perp / dm_perp`,
since `B_xc/m` is a scalar only while the two are parallel. The message now names both.

**User guide**: no change. `docs/guide/magnons.md`'s sentence ("A run with `nosource` gives an error,
because the kernel $B_{xc}/m$ is a scalar only while $B_{xc}$ is parallel to $\mathbf m$, which is what
the source-free projection breaks.") and `docs/guide/magnetism.md`'s stay true.

**README**: no change. **Slow tests for the user to run**: none.
