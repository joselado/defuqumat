# I76. `mixing_mode = 'robust'` x k-point pools, and x a checkpoint or `mixing_from`: done

**The number.** The check is an identity: the pooled run must be the one-pool run, and a resumed run
must be the uninterrupted one. It was measured on D22 (worktree `w-inc-I76-v2` at `623da84`, harness
`review/incompat/I76/harness.py`, log `harness2.log`, one sample each, 237 s in all) on two-atom
silicon on a 2x2x2 grid (`SILICON_8K` of `tests/unit/test_parallel.py`, `conv_thr = 1e-10`). The
ladder was forced (`robust.RUNGS` shortened to one rung, and a stall declared at every kept input),
so that each rung is taken at iteration 2 and everything the pooled loop now broadcasts is on the path.

| arm | iterations, 1 pool / 2 pools | energy, 2 pools minus 1 | same decisions |
|---|---|---|---|
| bottom rung (damped Hamiltonian mixing) | 12 / 12 | -1.8e-15 Ry | yes |
| LDOS rung (smeared, `nbnd = 8`, Gaussian 0.02) | 15 / 15 | 0.0 | yes |
| the mode as shipped | 7 / 7 | 8.9e-15 Ry | yes |

Rank 1's energy equals rank 0's bit for bit in every arm. "Same decisions" is the sequence of
(rung, kept, reason) in rank 0's `history`.

| resume arm, stopped at iteration 5 | iterations: whole, resumed, without the supervisor file | energy, resumed minus whole | iteration 6, resumed minus whole | iteration 6, no supervisor file, minus whole |
|---|---|---|---|---|
| bottom rung, 1 pool | 12, 12, 13 | -3.6e-15 Ry | -1.8e-15 Ry | 2.3e-3 Ry |
| as shipped, 1 pool | 7, 7, 7 | 7.1e-15 Ry | 0.0 | 0.0 (the record differs: `first` at 6) |
| bottom rung, 2 pools | 12, 12, 13 | 1.8e-15 Ry | -7.1e-15 Ry | 2.3e-3 Ry |

So the witness fires: with the supervisor's file removed the first iteration back is 2.3e-3 Ry away on
the bottom rung, and the run takes one more iteration, while with the file it is the uninterrupted run
to 7e-15. The stopped directory holds `scf_iteration.npz`, `scf_mixer.npz` and `scf_supervisor.npz`
(and, under two pools, the two rows files of iteration 5). The fast tests of `test_robust_mixing.py`,
`test_parallel.py`, `test_scf_restart.py` and `test_checkpoint.py` under `-m 'not slow'` pass on D22
(`fast2.log`, 93 passed, the QE tree linked into the worktree so that `test_scf_restart.py` does not
skip).

**What this does not cover.** No arm rejected a trial (`rejected = 0` in every run), so the retry path
`_combine(_kept, _proposal, scale)` after a resume is checked by the round trip of the file
(`test_the_supervisor_crosses_the_file_exactly`, every field to the bit) and not end to end. Under
pools a rejection changes only rank 0's next input, which reaches the others through the same
broadcast as a kept one. The LDOS arm is on an insulator, whose LDOS at `e_F` is about zero, so it
checks that every pool sums what rank 0's preconditioner asks for, not the preconditioner's physics.

**The old guard fired.** The entry said "Test: none", and the WIP this unit resumed from had already
removed the clauses, so the guard was fired from `126d6ec`'s source (`_refuse_robust` extracted and
called with `pooled = True`, `checkpoint_dir = 'x'`, `mixing_from = 'x'`): "k-point pools are not
implemented for it" and twice "a checkpoint does not carry the supervisor's state yet".

**What was missing, and where the entry was wrong.** The entry named two things, the supervisor's state
in the checkpoint and pool support. Both were right, and the pool half was larger than stated:

- *The checkpoint.* A third file, `scf_supervisor.npz` (`checkpoint.save_supervisor`), holds every
  field of `Supervisor` except the four that `run_scf` rebuilds from the input, every field of
  `HamiltonianDamping`, the bottom rung's `hamiltonian_in` (the Hamiltonian the next iteration
  diagonalises, which is not a function of the saved density), and the mixer's `beta` and
  `condition_limit`, which `save_mixer` treats as settings and the supervisor changes. A field added to
  either dataclass is carried or raises. The file is stamped with its iteration, and a resume whose
  checkpoint is another iteration does not use it and says so. A run in another mode removes a stale one.
- *`mixing_from` alone is not poured* (a choice taken the conservative way, and a question for you).
  Anderson can take a foreign history because it reads residual pairs, but the supervisor rebuilds a
  rejected trial as a density, `_combine(_kept, _proposal, scale)`, which would be the other run's. So
  `mixing_from` without a resumed state carries the mixer history and starts the line search from
  this input. The question: should a `mixing_from` with a `starting_from` of the same run pour it too?
- *Pools.* Only rank 0 judges a trial, as only it mixes, and its next input already reached the others
  through the broadcast of the mixed state. Four of its decisions act outside that state and were not
  broadcast: the step `alpha` that rescales `accuracy` on the bottom rung (the `ethr` schedule and the
  stop read it), the mixed Hamiltonian, the stop at that rung's floor (a `break` on rank 0 alone, which
  would have left the others waiting in the next broadcast), and **whether the LDOS preconditioner is
  installed**. The last is the one the entry did not see: `wants_ldos` changes what every pool's
  density pass sums and reduces, so a rung taken on rank 0 alone leaves the pools in different
  collectives.
- *A bug that was there already.* The LDOS branch of `stream_densities` never set `becsum` on a
  norm-conserving run, so it came back as `None` where the plain branch returns `()`, and `_mix` died
  zipping over it (D22 `debug.log`: `TypeError: 'NoneType' object is not iterable` at `_mix`, rank 1
  then waiting in a broadcast). By the code, this is any `mixing_mode = 'ldos'` on a norm-conserving
  cell under pools or `wfc_store = 'stream'`, not only the robust mode. Fixed in `623da84`, with
  `test_the_streamed_ldos_pass_hands_a_norm_conserving_run_an_empty_becsum`, which fails without the
  fix.
