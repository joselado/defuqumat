# I26. Real-time propagation x spin spiral: blocked

No number; the refusal stays, sharpened, and the entry's "Test: none" is now
`tests/unit/test_realtime.py::test_a_spin_spiral_is_refused_by_name` (no SCF).

**What is missing, as found in the code.** The entry's "two spheres at
`k +- q/2` under `k + kappa`" is right and understates it. Spinors themselves
run (P139 to P141), and `at_kcart` now takes a spiral's doubled list (I22), but
the propagator does not go through `at_kcart`: `realtime/propagate.py:_Chunk`
holds one `k0`, one `gcart`, one `mask` and one projector `core` per k-point,
built from `calculation.at_rows(rows)`, and every operator (`_project`,
`_expand`, `kinetic_nonlocal`, `band_form`, `overlap`) applies that one `vkb`
to both spinor components. A spiral needs each of these per component (rows
`ik` and `nk + ik` of the doubled list), `kappa` added to both centres, and the
radial table read at both `k + q/2 + G + kappa` and `k - q/2 + G + kappa`. The
local term goes through the `SpinorHamiltonian` template, which already
handles a spiral. The check would be the hydrogen or NiI supercell propagated
under the same pulse, current per cell. Not attempted tonight.
