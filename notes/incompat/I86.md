# I86. Gamma phonon x ultrasoft or PAW metal: done

Status: **done** for one spin channel, `nosym`, the whole cell, on the whole-k route. The
guard `_require_a_moving_overlap_regime` no longer stands in front of the dynamical matrix. It
stays for the Raman tensor, where the Sternheimer guard refuses every metal first anyway, and its
message now names the third derivative. The regimes beside the measured one each refuse by name
in `_require_a_measured_overlap_metal` and `_require_no_walked_overlap_metal`
(`defuqumat/response/phonon.py`). They refuse because they are unmeasured, not because a term is
known to be missing.

## What was missing, as found in the code

The entry named "which weight (`wg` or `2 wk`) the three tangents take". That is part of it,
and two more pieces were needed:

1. **A pair weight, not a choice between two weights.** A metal's Sternheimer state is
   `theta_mn (f_n - f_m)/(eps_n - eps_m) <m|dH - eps_n dS|n>` on the occupied pair. Here
   `theta_mn = wgauss((eps_m - eps_n)/degauss, 0)` is the second step of `orthogonalize`'s smeared
   branch. Subtracting the density matrix this generates from the exact first-order density matrix
   leaves `-W_mn S'_mn`, with `W_mn = f_n (1 - theta_mn) + f_m theta_mn`. This is QE's
   `compute_weight` `wgg`, which is used in `incdrhous` and `compute_nldyn`. `W` is symmetric. So
   the occupied block becomes `dpsi^ort_n = -1/2 sum_m psi_m S'_mn W_mn` at the k-weight `wk`
   (`pair_weights`, `orthogonality_states`). The `ort` half of `non_variational_response` (both
   `drhous` and `becsumort`) is accumulated at `wk`, and the `moved` half stays at `wg`. Doing the
   same algebra on the energy-weighted density matrix gives the multipliers' tangent
   `dLambda_mn = wk W_mn [<m|dH|n> - 1/2 (eps_m + eps_n) S'_mn]`, which has no row mask
   (`multiplier_response`'s metal branch). Both reduce to the validated insulator expressions,
   because there `W` is the occupied mask.
2. **The assembly could not be split as P28 splits it.** The norm-conserving metal takes the
   state tangent from a second `jvp` at `L[wk]`. For an augmented dataset the density is built
   from the states and the weights, so `L[wk]` puts the Hartree and XC kernels at the wrong
   density. Also, the cross term pairs the state tangent (at `wk`) with the augmentation charge's
   own motion (at `wg`) in one product, which no single-weight `jvp` gives. The fix carries every
   band twice in `_force_constants`: one copy at `wg - wk` with no tangent, and one at `wk` that
   carries `dpsi + ort` and `dLambda`. The ground multipliers split the same way. Every term of `L`
   is linear in the weights, so the primal is the ground state, the coordinate sees `wg` and the
   tangent sees `wk`. An insulator is not doubled (`state_weights is weights`).
3. **The Fermi shift.** The shift now counts `drhous`, as `solve_linter` does after
   `addusddens`. The two halves of `drhous` integrate to zero together in exact arithmetic, so
   this follows QE's order and is not a new term. PAW's `dbecsum` is shifted by `def becsum1`
   (`ef_shift`'s PAW branch). Without this, the one-centre potential of a PAW metal would
   respond to an unshifted `becsum`.

The entry's sentence about HOLES #12 and PAW-MODES 7 (`addusdynmat`, `drhodvus`) is stale. Those
terms were written in P39 and did not change here.

## What still refuses, each with a fast test (`tests/unit/test_overlap_metal_phonon.py`)

- symmetry on (`si-epsilon-us` with smearing): "implemented on a nosym run only";
- `nspin = 2`: "spin-polarized metal";
- `atoms=`: "partial dynamical matrix";
- the walked route, `memory_mode='memory'` or a streamed store (`chunked_phonon` has its own
  `ort` and multipliers without `W`): "k-chunk at a time";
- the Raman tensor of an ultrasoft metal (the generic metal refusal first, then the old guard,
  now worded for the third derivative).

The same file checks `pair_weights` (symmetric, equal to the projector's weight without
`alpha_pv`, equal to the occupied mask for a narrow smearing). The run on `-v3` read 9 passed and
1 failed. The failure was a wrong expectation in the test (it expected the walked guard to be
silent on an ultrasoft metal), and that test is fixed in the final commit, which was not rerun on
D22.
