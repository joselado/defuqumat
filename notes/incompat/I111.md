# I111. Fixed-spin-moment feedback constraint x `lspinorb`: done for `'fsm'` with `fsm_update = 'elk'` (2026-10-20); the secant and the per-atom schemes stay refused

Branch `incompat/I111` from master `6c5b3a36`. Every number on D22, one core per job through
`review/guide/slot.sh`, logs in `/l/ladovj1/review/incompat/I111/`, harness
`notes/incompat/I111-harness/harness.py` (worktrees `w-inc-I111-v4` at `b78a7359`, `-v5` at
`3c08f709`, `-v6` at `a9bc2e30`), one sample each.

**The number.** The fsm fixed point is the pair (density, `B*`) at which the density is
self-consistent under `B*` and its moment is the target. The identity, which shares no code with
the controller: hold `B*` fixed as a plain `b_field`, start from the converged fsm state, and the
first iteration must already be self-consistent with the moment on the target. On bcc Fe
(`Fe.rel-pbe-spn-rrkjus_psl.0.2.1`, `ecutwfc = 25`, `ecutrho = 200`, Marzari-Vanderbilt 0.05,
`noncolin`, `lspinorb`, `nosym`, `noinv`, shifted 2x2x2 mesh, 8 k-points), target 1.0 mu_B at
30 degrees from z in the xz plane, `lambda = 0.02` (the default gain), `FSM_TOLERANCE = 1e-5`,
`mixing_mode = 'adaptive'`, `mixing_beta = 0.05`, `conv_thr = 1e-10` (`r5-fsm.log`):

- fsm: converged in 293 iterations, `dr2` 8.0e-11, moment (0.4999964, 0, 0.8660230), `B*` =
  (-0.00497550, 0, -0.00830869) Ry, total -253.6828097230 Ry.
- `B*` held fixed from that state: first `dr2` **1.07e-10**, converged at iteration 2 with total
  -253.6828099449 Ry, **2.2e-10 Ry** from the fsm total, moment (0.5000053, 0, 0.8660444), 1.9e-5
  mu_B off the target.

**The alternative reads differently** (`r6-par.log`). `B*` projected on the target direction, so
that only the transverse part is dropped (1.55e-4 Ry), held fixed from the same state: first `dr2`
**5.8e-7**, 5400 times the whole field's. So the transverse field is part of the fixed point, and a
controller that got it wrong (a diagonal secant, a sign) would fail the identity. Left to run,
that field ends in the reversed moment (-1.048, 0, -1.816) after 129 iterations. That end is not
evidence about the coupling: the whole field, held fixed from a fresh start (`bfrom`,
`r4-fsm-ad.log`), also ends there (-1.078, 0, -1.799), because a field opposing a moment held
below its free value of 2.01 mu_B makes the constrained state a stationary point that is not a
minimum. Only the first iteration from the converged state is the identity.

**The term switched off** (`soc_scale = 0`, same cell and settings, `r5-soc0.log`): the fsm run
reaches `dr2` 1.28e-10 at the 1000-iteration cap (just above `conv_thr`), moment (0.4999987,
-0.0000064, 0.8660229), and its field held fixed from that state starts at `dr2` 1.29e-10 and then
runs away from that at-cap state (verifier), so at `soc_scale = 0` only the first held iteration is
an identity. Its total in the table is the at-cap value, -253.6854500 Ry; the verifier's converged
run reads -253.6854174 Ry. Its `B*` is purely longitudinal and longer:

| | `|B*|` (Ry) | along the target | transverse | total (Ry) |
|---|---|---|---|---|
| `soc_scale = 1` | 9.6845e-3 | -9.6833e-3 | **1.55e-4** | -253.6828097 |
| `soc_scale = 0` | 1.18939e-2 | -1.18939e-2 | **1.7e-7** | -253.6854500 (at the cap; converged -253.6854174) |

So spin-orbit coupling changes the field by 2.2e-3 Ry in length and adds a transverse part 900
times the coupling-free residue; the measurement can tell the coupling is on. The free moments
(`r4-free.log`) are 2.0128 mu_B with and 2.0207 without the coupling, both at 30.0 degrees.

**Convergence parameters** (k8 cell, target 1.0 mu_B; logs `r5-fsm`, `r5-tol`, `r6-tau*`):

Across the four gains the total spreads by 1.2e-10 Ry and `|B*|` by 7.6e-6 Ry. That is the same
size as what loosening the stops does at gain 0.02 (`conv_thr` 1e-8: 2.5e-6 Ry and 8e-11 Ry;
`FSM_TOLERANCE` 1e-3: 4.2e-6 Ry and 4.9e-10 Ry), so it is the stopping noise and not a gain
dependence of the fixed point. The transverse part does not move at the 1e-6 Ry level.

**Two more cells** (`r6-k27.log`, `r6-m15.log`). Shifted 3x3x3 mesh (27 k-points), target 1.0:
free run 30 iterations, 1.5434 mu_B; fsm 712 iterations, `B*` = (-0.00512300, 0, -0.00883447),
transverse 1.94e-5 Ry; held fixed, first `dr2` 1.04e-10, moment 2.8e-5 off. Target 1.5 on
2x2x2: 118 iterations, first `dr2` 5.2e-11, transverse 3.7e-7 Ry. So the transverse part is 1.55e-4
Ry on 2x2x2 and 1.9e-5 Ry on 3x3x3 at 1.0 mu_B, and 3.7e-7 Ry at 1.5 mu_B on 2x2x2, so the 1.5e-4
Ry quoted elsewhere in this record is one mesh and one target, and across the three cells the
transverse part runs from 3.7e-7 to 1.55e-4 Ry; by the
projected-field check it is part of the fixed point. Whether it equals the magnetic torque of the
anisotropy at that moment was not checked.

**What did not converge, and why it is not the refusal's business.**

- Anderson at `mixing_beta = 0.3`, 600 iterations: `dr2` 9.6e-3 (gain 0.02), 3.4e-2 (0.01) with
  the coupling, and 1.0e-2 at `soc_scale = 0` (`r4-fsm*.log`). The same failure without the
  coupling, so it is the fixed-gain field under Anderson in a noncollinear cell. `run_scf` reports
  it as not converged.
- Gain 0.01 with the adaptive mixer: `dr2` 1.4e-2 after 1500 (`r5-tau01.log`; the earlier
  implementer's one-k-point `asym14` read the same, 4e-2). Gains 0.015 to 0.04 converge.
- The earlier implementer's cells (`sym`, `asym`, `asym14`, `K_POINTS gamma` and one generic
  k-point, `r2-*`, `r3-*`, `sym-*`, `asym-*`): the **unconstrained** run with the coupling did not
  converge there either (400 Anderson iterations to 5.4e-7, `r2-free.log`), while `soc_scale = 0`
  converged in 24. So none of the failures on those cells, the fsm ones or the penalty ones, says
  anything about the controller; the WIP refusal ("measured not to converge") was a statement
  about the cell, and is withdrawn.
- The `'total'` penalty as a second check on the k8 cell, 1000 adaptive iterations each
  (`r5-pena.log`, `r5-penb.log`): `lambda = 0.5` reached `dr2` 2.1e-7, moment 1.0e-2 off,
  equivalent field (-0.00446, 0.00100, -0.00863); `lambda = 1`, 2 and 4 diverged (`dr2` 0.33,
  0.32 and 1.1, moments far from the target). So the penalty does not reach a regime where its
  field could be extrapolated, and the check is the fixed field above.

One thing seen and not followed: the total energy that `run_scf` prints at the first iteration of
a run started from a converged state (`starting_from`) under a fixed field is 7.7e-5 Ry off the
converged value (`bstart:it=1`, -253.6828868 against -253.6828097), while the second iteration is
2.2e-10 off. Only `dr2` and the moment of the first iteration are used above.

## User guide

`docs/guide/magnetism.md`, "Limits". Replace "The field schemes `'fsm'`, `'atomic fsm'` and
`'atomic fsm direction'` together with `lspinorb = .true.` give an error, because the search
updates each Cartesian component of the field from the same component of the moment, and
spin-orbit coupling couples the components. So there you use `'total'` or `'atomic'`." by:

> The field scheme `'fsm'` also runs with `lspinorb = .true.`, with the default update
> `fsm_update = 'elk'`. We checked it on bcc iron with a fully relativistic pseudopotential and
> a 2x2x2 k-mesh, with the target 1 Bohr magneton at 30 degrees from z. We took the final field
> and applied it as a fixed `B_field`, starting from the final density. The first iteration was
> then already self-consistent (`dr2` = 1e-10), and the total energy agreed to 2e-10 Ry. The
> final field is not parallel to the moment. Spin-orbit coupling adds a transverse part of
> 1.5e-4 Ry, and without this part the check fails. We ran it with
> `mixing_mode = 'adaptive'` and `mixing_beta = 0.05`, and it took about 300 iterations. With
> the Anderson mixer (`mixing_beta = 0.3`) it did not converge, with or without spin-orbit
> coupling, and with the gain `lambda = 0.01` it also did not converge. The gains 0.015 to 0.04
> converged. `fsm_update = 'secant'` with `lspinorb = .true.` gives an error, because the secant
> updates each Cartesian component of the field from the same component of the moment, and
> spin-orbit coupling couples the components. `'atomic fsm'` and `'atomic fsm direction'` with
> `lspinorb = .true.` give an error, because we did not test them. There you use `'total'` or
> `'atomic'`.
