# I85. Berry-phase finite field (`lelfield`) x spin spiral: done

**The number.** The P19 hydrogen chain at `occupations = 'fixed'` (gapped, 0.156 Ry in this code
and 2.12 eV in `pw.x`), the field `efield = 0.001` along `x` (`gdir = 1`, strings of 3 points,
`nberrycyc = 3`, `conv_thr = 1e-11`), each field run started from its own zero-field state. The
spiral at `q = b3/4` on 12 k-points (`kz = 0, 1/4, 1/2, 3/4`) against the 90-degree noncollinear
supercell on 3 (`kz' = 1/2`, the 12 folded). D22, CPU, one core, one sample each, in two runs
that agree to the last printed digit: the first with the gate bypassed in the harness
(`w-inc-I85`, `review/incompat/I85/h1.log`), the second on the committed code with the gate in
place, calling the two new test functions directly (`w-inc-I85-v2`, `h2.log`).

- `E(E) - E(0)` per primitive cell: spiral -2.971703180e-06 Ry, supercell -2.971711501e-06,
  **8.3e-12 Ry apart** (asserted at 1e-10). The absolute totals per cell differ by 8.7e-8 Ry at
  zero field, which is the Ewald difference between the two cells that P19 records (8e-8), so the
  identity is written on `E(E) - E(0)`, as in I14.
- `el_pol` of the supercell against four times the spiral's, modulo `2 pi fc_pol`:
  **8.9e-8 Ry a.u.** (2.3772766e-2 against 2.3772855e-2; asserted at 1e-6).
- **The control** (the up component's gather used for the down component too, which is what the
  code did before this change, run in `h1.log`): `E(E) - E(0)` misses the supercell by
  **6.9e-8 Ry** and `el_pol` by **5.5e-4**, so the identity would have read differently without
  the term.

The supercell is itself a magnetized spinor (absolute moment 3.75 Bohr mag in four cells), which
the gate refused too (I15's leftover). It is now checked against a new `pw.x` 7.5 run, serial
(`tests/data/qe/h-chain-90deg-fixed.in` then `-lelfield.in` from its states and potential;
`reference.out.h-chain-90deg-fixed`, `reference.out.h-chain-90deg-lelfield`): totals
**2.2e-9 Ry** at zero field and **1.0e-9 Ry** with it (`pw.x` prints 8 decimals; asserted at
3e-8), `el_pol` **2.0e-7** against `pw.x`'s 2.37729677e-2, inside the 2.4e-7 by which `pw.x`'s own
value moves between its last two iterations (asserted at 1e-6).

**What was missing**, as found in the code. The entry said "unread". The gate was the only stop:
the spiral reason was the bare string "a spin spiral", and the "nspin = 4 with a magnetization"
reason fired on every spiral as well, since a spiral always has `domag`. Behind them,
`BerryFieldSetup.build` built one Miller gather per k (from plane-wave row `ik`) and `_gathered`
applied it to both spinor components, which is right for a plain spinor and wrong for a spiral,
whose down component lives on row `nk + ik` (`k - q/2`). Now a spiral gets a `(nk, 2, npwx)`
gather, the up one from rows `(ik, jk)` and the down one from `(nk + ik, nk + jk)`, with the same
`e_gdir` shift at a string end for both, since both spheres move by the same `dk`; the whole-set
path and the streamed store's host path both take it. Nothing else changed: the occupied count
`NINT(nelec)`, the operator, the energy and the jump rule are the spinor's of I15.

**What stays refused**, each with a test that fires it on a spiral or a spinor: spin-orbit
coupling (`test_a_spinor_with_spin_orbit_coupling_is_refused`; a spiral cannot have it anyway),
an ultrasoft or PAW dataset, DFT+U and a metal
(`test_a_spin_spiral_still_refuses_a_metal_and_an_ultrasoft_dataset`). The analytic force route
refuses every spinor on its own, which is not this item's.
