# I67. Continuation across the spiral boundary (spiral source and plain target, or the reverse)

**Status: done**, for every case that has a term to add (after a fix round, below). Lifted, and measured, where
`spiral_q` is a reciprocal-lattice vector of the cell (an integer `spiral_q`, `q = 0`
included). At every other `q` the refusal stays, and it stays because of physics rather
than a missing term (the I29 shape): the laboratory spiral is not a density of this cell,
its cell-periodic part being zero (below). A DFT+U state across the boundary at a nonzero
integer `q` stays refused as the conservative choice, since `ns` was not measured.

## What was missing, as found

The entry said "the frame rotation of the transverse magnetization by `q.r`". The form is
right, and it is one real rotation of `(m_x, m_y)` by `-2 pi q.x` out of the spiral and
`+2 pi q.x` into one (`scf/continuation.py:_rotate_frame`, applied in `promote_density`).
What the entry does not say is that the rotation gives a density of the cell only when
`q` is a reciprocal-lattice vector. At any other `q` the laboratory spiral turns by
`-q.R` from cell to cell, its Fourier components sit at `G - q`, off the reciprocal
lattice of the cell, and its cell-periodic part is zero. The continuation that exists
there is into the supercell the spiral repeats in, which
`workflows.spiral.unfold_spiral_density` already builds, and a change of cell is what
`_check_grid` refuses for every continuation. So that half is physics, and its message
now says so and names the supercell route.

Three things the entry did not list, found in the surroundings of the guard:

- **`becsum` needs no phase.** The spiral pairs `vkb(k + q/2)` with `vkb(k - q/2)`, so the
  transverse block of `becsum` is already the laboratory value at the atom, and at an
  integer `q` it is the plain run's `becsum`. Measured on PAW above (1.2e-5 against 1.37
  for the per-atom phase).
- **The span crossed the boundary silently.** `_promote_rows` returned the spinors
  unchanged whenever the shapes agreed, so a `seed` or `none` continuation (which never
  reached the guard) handed coefficients on the spheres `k +- q/2` to a run that stores
  both components on `k`, and the reverse. It is now dropped with a warning whenever one
  run is a spiral and the other is not.
- **A DFT+U state is refused across the boundary at a nonzero integer `q`.** The
  norm-conserving spiral builds `wfcU` on the same two spheres, so `ns` should behave as
  `becsum` does, but no DFT+U spiral was measured. This is the conservative choice and
  an open question for the user.

## The fix round: two paths the first version opened

A verifier refuted the first version (87ff5bb8) on two paths, both measured on D22 in
`/l/ladovj1/review/incompat/I67-ver/`, and both are closed at e704f1de. The frame phase
itself survived every check put to it.

**A spiral into a collinear `nspin = 2` run at an integer `q` returned a corrupt density
with no error.** `_spiral_frame` tested only `transfer.source == 4`, so the frame was set
for a two-channel target too; `promote_density` projected to `(2, ...)` first and
`_rotate_frame` then read channels 1 to 3 of it, which JAX clamps rather than raises on,
so a `(4, 16, 16, 16)` stack reached a two-channel run (`c2.log`; 126d6ec raised). Under
it was a physics error: `_collinear_axis` ran in `_transfer` on the rotated-frame density,
where a laboratory helix is a uniform moment, so a helix read as collinear. The fix is a
refusal, `_refuse_spiral_demotion`, called in `_transfer` before the axis is read and
again in `_spiral_frame` for any target that is not `nspin_mag = 4`. It fires at every
`q` except `q = 0`, where the two frames are one. It is a refusal rather than "rotate to
the laboratory frame, then project" because at an integer `q != 0` the laboratory field
is a helix in the cell for any spiral that is not itself a helix in its own frame, and
the contrived case that would pass has no measurement; this is the conservative choice.
Measured at e704f1de (`/l/ladovj1/review/incompat/I67-fix/c2.log`, the verifier's own
`ver_c2.py`): `NotImplementedError` at `q = (0, 0, 1)` and at `q = (0, 0, 1/2)`, where
87ff5bb8 returned shape `(4, 16, 16, 16)` at the first. The unit test
`test_a_spiral_at_an_integer_q_does_not_cross_into_a_collinear_run` (`carry` and `auto`)
uses a source that is collinear along `x` in the spiral's frame, and fails at 87ff5bb8
with "DID NOT RAISE" (checked locally); a random vector field would not have told the two
apart, since the axis test refuses it anyway. `seed` still crosses and gives `(2, ...)`.

**`tau` crossed the boundary in the wrong frame.** The driver carried
`starting_from.tau` whenever its shape matched the target density's, and only
`promote_density` applied the frame. On the H chain with `tb09`,
`noncollinear_gga = 'kubler'` and `q = b3` (the verifier's `tau.log`), the spiral's
`tau` as it is was off from the fresh plain run's by 3.0e-1 in the transverse part,
against a maximum of 1.5e-1, and the plain run continued as the driver did it did not
converge in 200 iterations. Now `ContinuedState` carries the frame, and the driver's tau
rule has moved into `continuation.carried_tau`, which drops `tau` whenever a frame was
applied (and keeps the shape, `seed` and `none` rules it had). Dropping and not rotating:
rotated by the density's phase the difference was 1.47e-3, not zero, because `tau` pairs
gradients of components that sit at `k + q/2` and `k - q/2`, and nobody has shown the
phase alone carries it; dropping costs iterations and cannot be wrong. Measured at
e704f1de (`/l/ladovj1/review/incompat/I67-fix/tau.log`, one run each):
the driver path takes **78 iterations to `E = -0.405829400873` Ry**, bit-identical to the
`ContinuedState` path with no `tau` (78 iterations, `dE = 0`), against 200 unconverged at
87ff5bb8 and 99 from scratch. The landing state is 7.4e-4 Ry from the fresh plain run's,
which is the verifier's caveat that this `tb09` cell has more than one fixed point, not a
property of the continuation. Unit test: `test_tau_does_not_cross_the_spiral_boundary`
(dropped with a frame; carried, reshaped-away, seeded and depolarized without one), and
`test_a_spiral_crossing_records_its_frame_on_the_continued_state`.

Unit files on D22 at e704f1de, `-m 'not slow'` (`I67-fix/unit.log`): 250 passed, 6
skipped (`test_scf_restart.py`, which hardcodes the vendored path), in thirteen files
including `test_continuation_machinery.py`, `test_checkpoint.py`,
`test_spiral_integration.py`, `test_magnetic_input_guards.py` and
`test_sibling_refusals.py`.

Not covered, from the verifier: a k-mesh not invariant under the `G/2` shift (1x1x3 at
`q = b3`), where the spiral is a shifted-mesh copy of the plain run and the continuation
is a starting guess rather than the fixed point. That is not a correctness question.

A fourth fact for the record: the spiral and the plain run can have different dense grids
(silicon at `q = b3`: 16 against 15 along each axis, the spiral's box holding the sphere
displaced by `q`), and then the continuation is refused by `_check_grid` ("the cutoffs
have to match"). The chains here had the same grid on both sides. `nr1`/`nr2`/`nr3` are
refused at input, so there is no way today to put the two runs on one grid. This was not
touched.

What the continued run converges to is the target's own fixed point. After plain to
spiral at `q = G` the reported `magnetization_vector` is the integral of the rotated-frame
pair, which differs from the plain run's by the gauge (the `E(q + G) = E(q)` test in the
same file reads 0.540 against 0.205); that is not a failure.

## Guide and README

`docs/guide/magnetism.md`, Limits note of the continuation section (lines 357 to 360).
Delete:

> A source with a noncollinear magnetization does not cross into a spin spiral, or out of
> one, because a spiral measures $m_x$ and $m_y$ in the frame that turns with
> $\mathbf q$. A collinear source does cross, and a spiral continues from another spiral
> at any $\mathbf q$.

Replace with:

> A spiral measures $m_x$ and $m_y$ in the frame that turns with $\mathbf q$. So a
> noncollinear magnetization crosses into a spiral, or out of one, only when $\mathbf q$
> is a reciprocal lattice vector of the cell, for example `spiral_q = (0, 0, 1)` or
> zero. Then the code turns $m_x$ and $m_y$ by the angle $\mathbf q\cdot\mathbf r$, and
> the new run starts on its fixed point. For any other $\mathbf q$ the spiral repeats
> only in a supercell, so it gives an error. A DFT+U state does not cross this boundary.
> A collinear source does cross, and a spiral continues from another spiral at any
> $\mathbf q$. A spiral does not continue into a collinear run (`nspin = 2`), because
> its moment turns from point to point. The kinetic energy density of a meta-GGA run
> does not cross this boundary, so the new run builds its own.

README: no cell changes. The continuation paragraph under "Magnetism" (README.md:409 to
412) does not mention spirals.
