The `o-atom-fixed-lsda` edges are two members of the minority 2p triplet, which the
fixed filling cuts, so its gap is the eigensolver's residue and the edges themselves are
what is asserted, at `FERMI_EV = 2e-3`.

The `atom-lsda` HOMO agrees to 8e-5 eV. Its LUMO, the majority's first empty level,
is a state spread over the box, and `pw.x` disagrees with itself on it by 3.6 meV: the
same state (same pseudopotential, cutoffs, cell, total energy -31.40468356 Ry in both)
reads -0.4658 eV in the `K_POINTS gamma` run and -0.4694 eV in the full-sphere
`o-atom-fixed-lsda` run (`reference.out.o-atom-fixed-lsda:250`, band 5 of the majority).
This code gives -0.469423, the full-sphere value to 2e-5 eV. The test holds the LUMO to
the full-sphere line at `FERMI_EV` and to the gamma line at 5 meV. Reading the wrong band
would miss both by at least 0.15 eV (the minority's fifth level, -0.3196), and filling the
minority to two bands instead of four would give a LUMO of -6.63 eV, so the tolerance
discriminates.

Test: `tests/regression/test_lsda.py::test_the_band_gap_reads_both_channels_as_pw_x_does`
(slow, by its file's mark; 26 s for the file subset on D22 with both SCFs). Synthetic
cases, including a gap that crosses channels and the refusals:
`tests/unit/test_band_gap.py` (gate, under a second).

## What was missing

The entry's term was right in substance: each channel's band count. What the entry did not
say is that `BandStructure` has no way to know it, since it carries eigenvalues and not the
SCF's occupations, so the fix is an argument rather than a lookup: `tot_magnetization`
beside `nelec` (`nelup = (nelec + m)/2`, `neldw = (nelec - m)/2`, required whole, which
is `input.f90:784-800`'s condition), or `occupied = (n_up, n_down)` directly. The second
form is needed, not optional: QE's line for a `from_input` filling counts a band as
occupied above a 1e-3 weight (`get_homo_lumo`, `PW/src/print_ks_energies.f90:219-273`),
so one minority electron spread over the p triplet is four occupied bands, which no
integer `(nelec, m)` split reproduces. HOMO and LUMO are then taken over every k-point and
both channels, as `get_homo_lumo` does. A new `BandStructure.band_edges` returns the pair
and `gap` is their difference. `nspin = 1` and `4` are unchanged.

Still refused: `nspin = 2` with neither `tot_magnetization` nor `occupied`
(`NotImplementedError`, now naming both), and a split that is not whole in each channel
(`ValueError`). A smeared magnet's per-channel filling would need the SCF's occupations
carried onto the band structure, which is not done.

## User guide

`docs/guide/bands.md`, the "Limits" note. Delete:

> `bands.gap(nelec)` gives an error for a spin-polarized run (`nspin = 2`),
> because a gap at fixed filling is not defined for each channel. In this case
> you take it from `bands.eigenvalues_by_spin` with the occupation of each
> channel.

Replace with:

> For a spin-polarized run (`nspin = 2`), `bands.gap(nelec)` needs the filling
> of each channel. You give it as `bands.gap(nelec, tot_magnetization=m)`, or as
> `bands.gap(occupied=(n_up, n_down))`. Without one of them it gives an error.
> The gap is taken over both channels, so it can go from the top of one channel
> to the bottom of the other. `bands.band_edges(...)` gives the two levels.

## For the integrator

The `atom-lsda` LUMO is a finding beyond this item. This code runs that cell on the full
sphere with the `from_input` occupations and lands on `pw.x`'s full-sphere `fixed` value
to 2e-5 eV, so the spelling of the occupations is excluded as the cause and the 3.6 meV
sits with `pw.x`'s `gamma_only` route. That narrows `tests/regression/test_lsda.py`'s
module comment on `CASES`, which attributes the mismatch of the diffuse empty levels to
QE's `dq = 0.01` interpolation table; for this level the full-sphere agreement says
otherwise.
