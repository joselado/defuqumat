# I54. Partial dynamical matrix x k-chunked response

**Status: done.** `dynamical_matrix(response=<a walked response>, atoms=...)` now assembles
the subset's rows instead of refusing. Along the way I found and fixed a silent sibling:
the whole-k route took the same request and assembled it from the wrong atom's response.

## The number

The check is: the same kept response, assembled once whole and once with `atoms=(1,)`,
and the subset compared with the block `[1, :, 1, :]` of the whole matrix. The response is
the one `raman_tensors(keep_internals=True)` keeps, built from a host store (the walked
route) and from the device store (the whole-k route). Run with `threshold = 1e-12`,
`k_batch = 3`, `conv_thr = 1e-12`. D22, worktree `w-inc-I54-v2`, log
`/l/ladovj1/review/incompat/I54/harness2.log`, one run (it is a bitwise and round-off
comparison, so no median is taken).

| | si-epsilon-unshifted-nosym (nc, 64 k) | alas-epsilon-us-unshifted-nosym (US, 8 k) |
|---|---|---|
| walked, subset against the whole block of the same response | **0, bit for bit** (scale 0.2865) | **0, bit for bit** (scale 0.2219) |
| whole-k, subset against the whole block of the same response | 0 | 0 |
| walked subset against the whole-k subset | 1.2e-14 | 4.2e-14 |
| walked subset against a fresh subset solve (streamed, refined states) | 5.6e-15 (frequency 4.0e-13 cm^-1) | 3.7e-8 (frequency 1.7e-5 cm^-1) |
| whole-k subset against a fresh subset solve | 1.0e-14 | 3.7e-8 |
| **the old whole-k behaviour** (row r read as atom r's response) against a fresh subset solve | **2.57** on force constants of 0.29 | raised `IndexError` for `atoms=(1,)` (corrected at integration, see below) |

`on_row` fires `(1, 0), (1, 1), (1, 2)`, the subset's rows in the whole route's order.

The 3.7e-8 on ultrasoft AlAs is the same number on both routes, so it does not come from
the walk. Run 3 (`harness3.log`, AlAs, whole-k route) separates it:

| | max abs difference |
|---|---|
| kept response's whole matrix against a fresh whole-cell solve | **0, bit for bit** (whole matrix and atom-1 block; same 10 passes, same history) |
| fresh *subset* solve `atoms=(1,)` against the fresh whole-cell block | **3.7e-8** (10 passes, history 2.92e-20 at the last pass against 3.18e-20) |

So the kept response is exactly the fresh whole-cell solve, and the partial matrix is
exactly its block. The 3.7e-8 is a property of master's ultrasoft subset *solve*
(`atoms=` with `response=None`) against the whole-cell solve. That code was not touched
here. On norm-conserving silicon the same comparison reads 1e-14, so the gap is specific to
the ultrasoft subset path, and it shows up as a different loop history. I did not look
further. It is 1.7e-5 cm^-1 in the frequency. It is an open question for the integrator
(OPEN.md): is it the joint mixer taking a different path, or a term of P39's subsetted
tangents? The slow test therefore uses the fresh whole-cell block as its reference,
not a fresh subset solve.

## What was missing, as found

The entry said "unread". Here is what the code needed:

- **Walked route** (`response/phonon.py:dynamical_matrix`, the `walked is not None`
  branch). The refusal stood in front of `StreamedDisplacements.force_constants`. That
  function walks `self.modes` and writes row `row`. No physics was missing. A subset needs
  `nosym` (`_require_a_subsettable_regime` checks this before), and with `nosym` nothing
  couples the modes. So the rows of a response solved for every atom are the subset's
  response. The term that was missing is a row map: `force_constants(..., atoms=)` now
  reads each mode from row `self.atoms.index(atom)` of every per-mode store (`dpsi`,
  `drho`, `dbecsum`, the overlaps and the multipliers) and writes it to the subset's row.
  `Phonons.induced_density` is cut the same way.
- **Whole-k route, a silent sibling.** `_whole_k` with `response` given handed
  `response.dpsi` (every atom) to `_force_constants(..., atoms=chosen)`, which reads
  `dpsi[row]` with `row` running over `chosen`. So `atoms=(1,)` assembled atom 1's
  tangents with atom 0's response, and nothing raised an error. On an ultrasoft dataset,
  `multiplier_response` paired the all-atom `bare` with the subset's overlap derivatives
  as well. The fix is `_response_rows`, which cuts `dpsi`, `drho`, `bare` and every
  `extras` entry to the subset's rows. A response that already has exactly `len(atoms)`
  rows is taken as the subset's own, as before. Any other row count is refused
  (`ValueError`, "cannot be matched to atoms"). The table gives the size of the old error.

**Corrected at integration (`notes/INCOMPATIBILITIES-T2.md`).** The AlAs cell of the table's last
row read 5.5e-3 in the implementer's record, and that number is not what the old code does. The
verifier ran the same harness on `phonon.py` and `chunked_phonon.py` checked out from `126d6ec`
(D22, `/l/ladovj1/review/incompat/I54-ver/h-rev.log`): on ultrasoft AlAs and on PAW silicon the old
whole-k route raised `IndexError: index 1 is out of bounds for axis 0 with size 1` for `atoms=(1,)`
and for `atoms=(0,)`, and for `atoms=(1, 0)` it ran and was 9.455e-1 (AlAs) and 6.798e-1 (PAW Si)
off the fresh block. On norm-conserving silicon it ran, 2.570 off for `(1,)` and `(1, 0)` and 0 for
`(0,)`, as the table says. So the silent wrong answer was on norm-conserving cells and on a reordered
subset; a single augmented atom crashed instead.

Still refused, each with a test:

- a subset on a symmetrised run, with a walked response as well
  (`test_a_walked_response_still_refuses_a_symmetrised_subset`);
- `nspin = 2` on the walked route, with a kept response as well
  (`test_a_walked_response_still_refuses_nspin_two`), and through the front door as before
  (`tests/regression/test_lsda_response.py::test_the_walked_dynamical_matrix_and_the_strain_response_still_refuse_nspin_two`,
  which passed in the run on D22);
- a response whose row count matches neither the cell nor the subset.
