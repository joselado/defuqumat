# I15. Berry-phase finite field (`lelfield`) x spinor: done

**The number.** `tests/regression/test_berryfield.py::test_a_nonmagnetic_spin_regime_is_the_unpolarized_field[noncolin=.true.-...]`,
D22 (CPU, one core, `w-inc-finitefield-v3`, log `review/incompat/finitefield/spinor-3.log`; the same figures
in `spinor-2.log`), one sample: the pw_electric chain on Si8 (63 k-points as 9 strings of 7,
`efield = 0.001`, `conv_thr = 1e-11`) run with `noncolin = .true.`, no spin-orbit coupling and no
magnetization, against the `nspin = 1` chain. Totals **7.1e-15 Ry apart at zero field and 2.8e-14 with
it**, `E(E) - E(0)` **2.1e-14** (asserted at 1e-9), `el_pol` **5.2e-11** Ry a.u. (asserted at 1e-6),
`ion_pol` exact, seven iterations both; the autodiff force matches `pw.x`'s `reference.out.si8-lelfield`
at the file's 1e-6 Ry/bohr (`test_a_nonmagnetic_spin_regime_has_the_unpolarized_forces[noncolin=.true.]`).
The identity is the one `c_phase_field` implies: 32 spinor bands of one electron each, no factor 2,
against 16 bands of two electrons doubled, which on a Kramers-degenerate manifold is the square of the
same determinant.

**What was missing**, as found in the code, and where the entry was wrong. The entry said "the spinor
duals"; the duals needed nothing. Three things were missing: (1) `SpinorHamiltonian`
(`hamiltonian/noncollinear.py`) had **no slot for `H_E` at all**, so the first run died in
`eqx.tree_at(lambda h: h.berry, ...)` with `'SpinorHamiltonian' object has no attribute 'berry'`; it now
has one, in `_applied` and `matrix`, on the `2 npwx` vector as `h_epsi_her_apply` does with `npol = 2`;
(2) the Miller gather between neighbouring k-points was applied to a `(nk, nb, npwx)` block, and a spinor
is `2 npwx` with its components end to end, so `_gathered` now gathers each component with the same index
(`tests/unit/test_berryfield.py::test_a_spinor_is_gathered_component_by_component`); (3) the occupied count
is `NINT(nelec)` (`h_epsi_her_set.f90:225`) and `el_pol` has no factor 2, since `nspin = 4`.

**What stays refused**, each with its test in `tests/unit/test_berryfield.py`: a spinor with spin-orbit
coupling (`test_a_spinor_with_spin_orbit_coupling_is_refused`) and a magnetized spinor
(`test_a_magnetized_spinor_is_refused`). Both would run the same code, and neither has an identity or a
`pw.x` number measured here. The analytic force route refuses every spinor run on its own, field or not,
which is not this item's.

**User guide**, `docs/guide/electric-field.md`, "Limits" note, second paragraph: the replacement given in
`I14.md` for "It gives an error for `nspin = 2` and spinors." covers this item.
